# 桌面工作台体验收紧设计

## 目标

解决桌面端 `/new` 与 `/reports` 的大面积无效留白、字号层级跳跃、标题和说明对齐不一致的问题；让用户在选择 ZIP 后可以撤销当前文件选择。

本轮仅调整桌面端网页体验，不新增移动端布局、数据库字段、API、Worker 行为或 Storage 删除操作。

## 已确认的方向

保留左侧工作台导航和现有浅色 SaaS 风格，采用紧凑、左对齐、以操作为中心的内容布局：标题与主操作处于同一行，内容区最大宽度稳定，空状态高度受控。

## 页面设计

### 工作台框架

- 保留 220px 左侧导航，当前路由具有清晰的浅色背景和描边高亮。
- 主内容区使用约 1180–1240px 的稳定宽度与 32–40px 桌面内边距。
- 面包屑、标题、说明按左边界对齐；不再使用超大居中标题或两端分散的说明文本。
- 页面标题使用约 36–40px，区块标题使用约 20–24px，正文与辅助文字保持 14–16px 的连续层级。

### 我的报告

- 标题行：左侧为“我的报告”和一句说明，右侧为“+ 新建验收”。
- 空状态卡片高度收紧到约 190–220px；保留居中的空状态文案和行动按钮。
- 有报告时，标题行与报告列表保持相同的内容宽度和左对齐边界。

### 新建验收与 ZIP 选择

- 缩短介绍区，让表单卡片成为页面主要视觉焦点。
- 选择 ZIP 后，以文件名和大小替代笼统的“已选择”文本。
- 文件条目右侧提供文字按钮“移除 ×”。点击后清空浏览器文件输入和当前前端状态，恢复为未选择状态。
- “移除 ×”不调用 Storage 删除、不修改已创建任务，也不影响后端 ZIP 安全校验与用户隔离逻辑。

## 实现边界

- 复用现有页面、工作台 CSS 和 ZIP 上传状态；不改 Route Handler、Supabase RLS、Storage 路径、任务创建契约或 Worker。
- 添加针对 ZIP 移除行为与桌面页关键文案/结构的前端测试。
- 先让新增测试在旧实现上失败，再写最小实现；最后运行 Web 测试、lint、typecheck，并用桌面浏览器视图检查布局。

## 验收标准

1. 桌面 `/reports` 的标题、说明和主操作在同一紧凑内容区内，空状态不再占据大面积页面高度。
2. 桌面 `/new` 中选择 ZIP 后可见文件名、大小和“移除 ×”；点击后文件选择恢复为空且可以重新选择文件。
3. 当前页面导航高亮明确，标题、区块标题、正文和辅助文字层级连续。
4. ZIP 移除不触发远程删除，不影响现有 ZIP 校验、创建任务、RLS 与 Worker/Web 边界。
5. Web 测试、lint、TypeScript 通过；全仓格式基线不作为本轮门禁。
