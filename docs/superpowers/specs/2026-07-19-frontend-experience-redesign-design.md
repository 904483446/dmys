# VibeVerify 前端体验重构设计说明

## 目标

在不改变认证、权限、API、数据结构、任务创建和报告导出逻辑的前提下，将现有页面重构为可信、清晰的现代 SaaS 验收产品体验。

## 设计方向

面向非技术用户的开发者工具：冷静的中性色为主、单一橙红风险强调色、清晰栅格和有限圆角。参考页面仅借鉴高留白、层级化模块和精致状态反馈；不复制其版式或素材。避免泛后台、聊天机器人和过量动效。

## 统一规则

- 以页面容器、导航、标题区、状态标签、操作按钮和信息面板构成可复用视觉语言。
- 桌面使用最大宽度内容区；窄屏按单列重排，标题不会被单字断行。
- 动效仅用于按钮按压、进入淡入与状态反馈，并遵循 `prefers-reduced-motion`。
- 所有现有链接、表单字段、路由、aria 属性和 API 调用保持不变。

## 页面改造顺序

### 1. 首页

使用左右分栏首屏：左侧说明价值并保留“新建验收”，右侧显示固定演示报告的产品化预览。标题固定为可读的两行结构，取消超大字号与负字距造成的断行。

### 2. 登录与内测码激活

保留 Supabase 邮箱 OTP、第三方登录、内测码校验和现有跳转逻辑。登录页明确登录目的、验证码发送状态和可用入口；内测码激活页解释邀请制边界、隐私承诺和激活后的下一步。

### 3. 新建验收

保留来源选择、PRD/ZIP 上传和提交逻辑；用步骤说明、隐私边界和显式校验反馈组织表单，降低首次使用门槛。

### 4. 报告列表

保留现有任务数据与轮询；每个任务展示状态、创建时间、最近结论和可继续操作入口，空状态直接引导创建验收。

### 5. 报告详情

顶部先回答结论、评分、置信度和下一步；随后依次展示已验证功能、问题和修复建议、报告对比。证据与风险采用可扫描的分区，不改变报告 DTO 或导出内容。

## 验收与边界

- 每次只改造一个页面，先补/调整该页面渲染测试，再实现样式和组件。
- 每页完成后执行页面测试、`pnpm lint`、`pnpm typecheck`，并用桌面与窄屏截图检查。
- 不新增 UI 框架或图标库；沿用 Next.js、React 与原生 CSS，避免无关依赖升级。
