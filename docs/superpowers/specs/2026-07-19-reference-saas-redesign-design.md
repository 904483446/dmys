# VibeVerify 参考界面驱动的视觉重构设计

## 目标

在不改变现有页面功能、路由、API、权限、状态管理或数据结构的前提下，重构 VibeVerify 的视觉基础和页面表达。产品应呈现为可信的 SaaS 验收工具：官网具有明确转化路径，登录后的工作区具有专业、清晰、可扫描的业务界面。

## 参考解读

### Landing：Cliento 的视觉原则

- 明亮、留白充足的浅色画布，带有轻柔的环境层次，不复制云朵或原图素材。
- 单行顶部导航、居中的价值主张、紧凑的说明文字和一个主 CTA。
- 主 CTA 使用深色底，并以橙色方形箭头作为唯一高饱和行动强调。
- Hero 下方使用能力捷径和可信元素，而不是大量同质卡片。
- 仅 Landing 的主标题使用高对比展示字体；正文和产品 UI 均为无衬线字体。

### 应用内：Vendor Dashboard 的视觉原则

- 白色产品壳，窄侧栏、顶部面包屑、轻量工具图标和一致的内容网格。
- 卡片以细边界和充足内边距组织，数字、状态和趋势优先于装饰。
- 数据与可操作内容采用不同的模块层级：顶端指标、主体分析区、下方明细列表。
- 蓝色只用于链接、图表和主要交互；绿色用于通过，橙红用于风险或失败。

## 视觉系统

| 层级 | 决策 |
| --- | --- |
| 基础背景 | 冷白和极浅蓝灰，不使用米白编辑纸张背景。 |
| 品牌强调 | 主要行动使用深色按钮 + 橙色箭头块；产品内主要交互使用明亮蓝色。 |
| 状态颜色 | 通过为绿色，风险/待处理为橙色，失败为红色，信息为蓝色。 |
| 边框与阴影 | 使用极浅灰边框和克制阴影，不使用硬描边加偏移投影。 |
| 圆角 | 统一中等圆角，避免夸张胶囊形状。 |
| 字体 | Landing 标题可采用高对比展示字体；其余文字、表单、表格、指标统一无衬线字体。 |
| 动效 | 仅限 CTA、卡片悬停、筛选和状态变化的短反馈；支持减少动态效果。 |

## 页面设计

### 1. 首页

1. 顶部导航：品牌、产品入口、工作方式、价格/资源占位入口、登录和主 CTA。现有可用路由优先保留，未实现项不创建虚假链接。
2. Hero：一句聚焦验收价值的标题、一段不超过两行的说明、开始验收 CTA。右侧或下方展示真实结构的报告预览，不伪造外部产品截图。
3. 能力捷径：目标与验收标准、浏览器运行证据、可执行修复建议三项，以图标和短语表达。
4. 信任与流程：使用真实产品能力或流程节点，不放未经授权的客户 Logo。
5. CTA：引导至既有 `/new`，保留未登录时的现有跳转逻辑。

### 2. 登录与内测码激活

- 使用简洁的浅色营销外壳，与首页共用品牌、导航节奏和 CTA 风格。
- 表单采用无衬线产品控件、清晰标签、可见焦点态和统一错误提示。
- 邮箱 OTP、Google、GitHub 登录和内测码激活流程、字段、跳转保持不变。

### 3. 新建验收、报告列表和报告详情

- 建立共享应用壳：窄侧栏或可折叠移动导航，顶栏显示面包屑、页面标题和必要行动。
- 新建验收：项目来源、需求输入、上传和提交状态按工作流分区；字段顺序、提交 API 和额度提示不变。
- 报告列表：顶部可扫描的概览，任务表/列表展示状态、更新时间、评分或结果摘要和查看入口；轮询不变。
- 报告详情：按“验收结论 → 评分与可信度 → 证据 → 问题 → 修复下一步”排布。顶端指标卡使用状态色，证据和问题采用清晰的双栏或分区布局；导出、复制提示词、重跑和比较能力保留。

## 响应式与可访问性

- 桌面端内容容器和侧栏形成稳定栅格；小于 768px 时侧栏折叠，指标卡和双栏内容改为单列。
- 保持键盘可达、原生焦点态、可读对比度和减少动态效果偏好。
- 不改变表单字段名称、顺序、路由、主导航的既有含义或 analytics 触发点。

## 实施顺序与验收

1. 建立颜色、字体、间距、按钮、输入框、卡片、状态标签和应用壳的基础样式。
2. 改造首页并提供桌面/移动端截图确认。
3. 改造登录与内测码激活。
4. 改造新建验收、报告列表和报告详情，每页独立测试与截图核验。
5. 最终执行 lint、typecheck、test、production build、依赖审计和可访问性/响应式检查。

## 不在范围内

- 不新增 UI 框架、图标库、图表库或营销素材服务。
- 不修改 Supabase、Worker、RLS、任务执行、报告 DTO、导出脱敏、权限或 API 合约。
- 不复制参考页面的文案、Logo、图像、图表数据或完整布局。
