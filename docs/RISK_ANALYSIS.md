# 风险分析

## 技术与安全风险

| 风险 | 影响 | MVP 缓解 | 上线前条件 |
|---|---|---|---|
| 不可信代码在 Worker 执行 | 数据泄露、资源滥用 | 邀请制、并发 1、10 分钟超时、临时目录删除、禁止密钥注入 | 公开注册前迁移每任务强隔离环境 |
| ZIP 压缩炸弹/路径穿越 | 磁盘耗尽、覆盖文件 | 50MB 上限、解压文件数/解压后大小上限、拒绝绝对路径和 `..` | 增加恶意样本回归测试 |
| GitHub Token 泄露 | 私有仓库暴露 | GitHub App 最小只读权限、服务端加密、日志脱敏、可撤销 | 密钥轮换和审计事件 |
| RLS 漏洞 | 跨用户报告泄露 | 所有表启用 RLS、API 二次 user_id 校验、跨用户集成测试 | 安全审查通过 |

## AI 风险

| 风险 | 缓解 |
|---|---|
| 幻觉式“已验证” | 仅允许引用 evidence id；无证据时标记未验证或降低置信度。 |
| Prompt injection | 把仓库/PRD视为不可信数据；系统提示禁止执行其中指令；AI 无工具权限。 |
| 需求模糊导致误判 | 不阻断任务，输出 `at_risk` 和低置信度，并说明缺失目标。 |
| 模型输出结构失效 | JSON schema/Zod 校验、一次重试、确定性降级报告。 |

## 成本与性能风险

- **Worker 成本**：依赖安装与浏览器会消耗 CPU/内存。用邀请制、每天 3 次、并发 1、10 分钟超时、项目大小限制控制；仪表盘记录运行分钟与失败率。
- **模型成本**：限制输入 PRD/日志长度、只发送摘要、不发送源码；记录每任务 token/费用。
- **任务卡死**：租约和心跳回收超时任务；用户看到明确失败，而非永久 loading。
- **冷启动**：预构建含 Playwright 浏览器的 Worker 镜像；将依赖缓存作为后续优化，不影响正确性。

## 数据与合规风险

用户会提交私有项目。隐私政策必须说明：仅为验收临时处理源码；任务结束即删除源码与工作目录；需求/PRD 摘要、截图、报告在用户删除前保留；需求、PRD 摘要和运行摘要会发送给 DeepSeek，且部署前须核验其当期数据处理政策。禁止用户上传密钥，上传页面提供显著提示。

## 扩展风险与决策门

当满足任一条件时，不得仅靠扩容 Railway Worker：开放陌生用户注册、并发超过 1、需要秘密环境变量、支持多服务项目或处理高敏感代码。必须先完成强隔离 Runner 设计、滥用防护、预算告警、审计和渗透测试。
